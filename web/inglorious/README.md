# Inglorious Web app

The [web interface](../README.md) built with [Inglorious Web](https://github.com/IngloriousCoderz/inglorious-forge): lit-html templates, TypeScript, Inglorious UI with the material theme, and Inglorious Charts, on Vite. Same features as the [React app](../react/README.md). Scaffolded with `pnpm create @inglorious/app` (TypeScript template, lit-html, Inglorious UI with the material theme, routing).

## Running

Needs Node 22 and pnpm, and the API running on port 8000 (see the [main README](../../README.md#quick-start)):

```bash
pnpm install
pnpm dev                       # http://localhost:5173 (or the next free port)
API_URL=http://127.0.0.1:8001 pnpm dev   # if the API runs on another port
```

The dev server forwards `/api/*` to the API and adds the API key from `api/.env`, with the same proxy as the React app (see [`vite.config.ts`](vite.config.ts)). Open http://localhost:5173/monitoring, then run `demo/demo.sh drift` to watch it change.

| Command          | Does                                                           |
| ---------------- | -------------------------------------------------------------- |
| `pnpm dev`       | Development server with hot reload                             |
| `pnpm build`     | Type-check, then build into `dist/`                            |
| `pnpm typecheck` | Type-check only                                                |
| `pnpm test`      | Unit tests (vitest)                                            |
| `pnpm lint`      | Lint (eslint): fails for now, see Notes                        |
| `pnpm gen:api`   | Regenerate `src/api/schema.d.ts` from `../../api/openapi.json` |

## Structure

```
src/
  api/schema.d.ts         API types, generated by pnpm gen:api (don't edit)
  api/client.ts           typed fetch wrapper: same file as the React app's
  lib/stats.ts            /stats to chart rows and labels: same file as the React app's
  store/                  the store: entities, routes, middlewares (Redux DevTools in dev)
  types/model.ts          the model version chip; loads the manifest when created
  pages/classify.ts       Classify page: input, results, the predict request
  pages/monitoring.ts     Monitoring page: refreshes /stats while its route is shown
  pages/not-found.ts      for unknown paths
  components/             stat-card, shares-chart: plain renderers, no store wiring
  app.ts                  app bar, tabs, the current route's page
  main.ts                 styles, light or dark following the system, mount
types/                    entity types, and declarations for @inglorious/charts
```

## Same app, two models

The features are the same as in the React app; where the state lives is what differs. Here every piece of state is in a store entity, changed only by event handlers:

| Concern                    | React app                                 | Inglorious Web app                                                                                         |
| -------------------------- | ----------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| Text area, results, errors | `useState` in `ClassifyPage`              | The `classify` entity, changed by `inputChange` and `predict*` handlers                                    |
| A request                  | `async` function in the component         | `handleAsync("predict", …)`: `predict`, `predictStart`, `predictSuccess`, `predictError`, `predictFinally` |
| Refreshing `/stats`        | `usePolling` while the page is mounted    | The `monitoring` entity listens to the router's `routeChange`: starts on its route, stops on any other     |
| Model manifest             | The root route's loader (TanStack Router) | The `model` entity loads it in `create`                                                                    |
| Routing                    | TanStack Router, code-based routes        | The built-in Router entity; paths name the entity whose page they render                                   |
| Tabs as navigation         | `createLink(Tab)`, real links             | `Tabs` with `onChange` notifying `#router:navigate`                                                        |
| Chart hover state          | Inside Recharts                           | A chart entity per chart (`categoryChart`, `confidenceChart`)                                              |
| Debugging                  | React DevTools                            | Redux DevTools: every event and state change                                                               |

## Notes

Things found while building it, with Inglorious packages as of 2026-10-19 (web 6.6.1, ui 8.1.1, charts 10.0.7, eslint-config 1.1.2). Each workaround is commented in the code.

- **`pnpm lint` fails.** `@inglorious/eslint-config` 1.1.2 on npm declares a `./typescript` entry, but `typescript.js` isn't in the published package, and it has no type declarations. The monorepo has both, under the same version number, so they weren't published. Until a new version is out, `eslint.config.ts` is left out of type-checking ([`tsconfig.node.json`](tsconfig.node.json)).
- **Charts have no TypeScript declarations**, so [`types/inglorious-charts.d.ts`](types/inglorious-charts.d.ts) declares what this app uses.
- **Chart axes**: the Y axis has no tick formatter, so shares are plotted in percentage points and the card titles say "%". The legend names each series after its data key, so the keys are `Live` and `Baseline`. The legend has its own palette, so it gets the bars' colours.
- **Chart colours in dark mode**: the renderers draw text and lines with fixed colours tuned for a light background, and don't read the `--iw-chart-*` variables. CSS takes precedence over SVG attributes, so [`app.css`](src/app.css) makes them follow the theme.
- **Linear `Progress` ignores `color`**: it's applied by the circular variant only. Passing the class (`iw-progress-warning`) through `className` works.
- **`Button`'s default `color` is a neutral `"default"`**, which its type doesn't list; the Classify button sets `color: "primary"`.
- **A default `Chip` is invisible on white**: in the material light theme its background is the theme's white secondary background, the same as cards and tables. The category chips use `color: "secondary"`, a grey pill like Material UI's default chip.
- **`Tooltip` declares `onClick` as required**, though it opens on hover; the model chip passes an empty one.
- **`Tabs` can't select no tab through its types**: `undefined` falls back to the first tab, and `null` isn't allowed, so the Not Found page passes a value no tab has.
- **`Table` never wraps its cells** (`min-width: max-content`) and scrolls instead; the results table lets the long _Alternatives_ column wrap.
- **No `--template` or `--syntax` flags in `create-app`**: the project name, template and syntax are prompts only, so scaffolding can't be fully scripted.
